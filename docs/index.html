What it does

Everything here works today. Nothing on this page is a plan.

Torrents, magnets and URLs

Double-click a .torrent, paste a magnet link, or give it an http(s) URL that serves one. For a magnet it fetches the file list from peers before anything else happens.

Lives in the menu bar

Close the window and it carries on seeding in the background. The menu bar icon shows the rates without you opening anything.

SHA-1 on every piece

Checked before it reaches the disk, and bad data is refetched. It resumes by hash-checking what is already there, so there is no separate state file to corrupt.

Speed limits that hold

Upload and download ceilings, shared across every torrent at once, so a download does not take the house off the internet.

A ratio that survives restarts

Cumulative shared bytes counted across runs, which is the number a tracker actually reflects — not a figure that resets every time you quit.

Asks the router for the port

NAT-PMP first, then UPnP IGD. When neither works it says so plainly rather than showing a green light it has not earned.

3.5 MB, and that is the whole thing

No Java, no Electron, no runtime, no third-party dependencies. Drag it to Applications and the install is done.

Liquid Glass on macOS 26

On floating surfaces, with the older materials below that. It degrades rather than breaking.

🎯 Deliberately small — no DHT, no PEX

BITT is built for one situation: you get .torrent files and magnet links from a site you already use, and you want them downloaded without fuss. It works with any torrent or magnet that carries trackers, which is effectively everything a site hands you.

It does not do DHT (BEP 5) or PEX (BEP 11), and that is a decision rather than a gap:

  1. Private trackers forbid both. Those torrents set the private flag, and announcing them to the DHT is a good way to lose your account. For the intended user it is not merely unnecessary, it is harmful.
  2. Site magnets already carry trackers, so the DHT would add nothing in practice.
  3. A DHT node is never idle. It answers UDP from the whole world whether or not you are downloading, which works against the point of a small client — and it is another ~1,000 lines to carry.

The consequence: a bare magnet with only xt=urn:btih:… and no &tr= will not work. BITT says so in the add dialog instead of leaving it stuck at 0%.
